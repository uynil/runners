## 工作约定

- Linear 是需求、规格、实施任务及进度的唯一任务来源。
- 通过已连接的 Linear 工具读取、创建和更新任务。
- 创建任务时指定 TEAM M 和上述 Runners 项目。
- 发布规格时，创建或更新 Linear 中的规格任务；实施任务关联该规格。
- 拆票时每个实施任务单独创建 issue，记录验收条件和依赖关系。
- 获取任务时优先使用 MEA 编号或用户提供的 Linear URL。
- 更新前读取现有任务，保留已有内容、评论和关联。
- 调研与探索结果写回对应任务或项目文档。
- `.scratch/` 可用于临时工作，不作为另一套任务列表。
- GitHub 用于代码和 PR；分支与 PR 引用对应的 MEA 编号。
- 分类规则见 `triage-labels.md`。

## Wayfinding

- 使用一条 Linear 父任务作为探索地图，维护笔记、已定决策和待解问题。
- 每个子问题单独创建子任务，在描述中记录类型。
- 使用 Linear 阻塞关系表达依赖。
- 从未认领、未完成且无阻塞的任务中按编号顺序领取。
- 领取时记录认领信息；解决后记录答案、完成任务，并将结论和链接写回父任务。
